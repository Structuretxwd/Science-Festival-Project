# 校园智能体「小助手」

一个**离线优先**的校园问答智能体。默认不联网、不花钱、断网也能答；检测到 API Key 且网络可用时，置信度不足的问题会自动升级给大模型（DeepSeek）补充作答。

同一套检索引擎用 **Java** 和 **JavaScript** 各实现了一份，读同一份知识库与同一份参数文件，并且有脚本逐行校验两边结果完全一致。

---

## 亮点

| | |
|---|---|
| **离线可用** | 不依赖任何在线服务。断网、无 Key、比赛现场网络故障，都能正常回答校内问题 |
| **会知道自己不知道** | 用「加权覆盖率 + 与第二名的分差」两个指标判断置信度，把握不住就老实说没学到，不硬答 |
| **自动升级大模型** | 中/低置信的问题才走联网；高置信直接返回知识库原文，不浪费 token、结果可复现 |
| **双引擎等价** | Java 与 JS 两份实现共用数据与参数，`node tools/equiv-check.js` 逐行比对，防止两边慢慢长歪 |
| **数据诚实** | 23 条来自学校公开信息（标注出处），19 条是模拟示例数据并显式打标，绝不冒充真实校方数据 |

## 快速开始

### 环境要求

- **JDK 17 或更高**（实测 JDK 21；用到了 `java.net.http.HttpClient` 与 `com.sun.net.httpserver`）
- **Node.js**（仅自测脚本需要，选装）
- 不需要 Maven / Gradle，也不需要任何第三方依赖

### 运行 Java 版（推荐，双击即可）

```
java\run.bat
```

它会自动编译、启动本地服务，并用 Edge/Chrome 的 `--app` 模式弹出一个**没有地址栏的窗口**，看起来就是个桌面应用。控制台会打印访问地址和当前模式。

自动化测试或不想开窗口时：

```
java\run.bat --no-browser
```

### 运行纯前端版（GitHub Pages）

把 `docs/` 目录直接发布到 GitHub Pages 即可。没有后端时，页面自动切换到本地 JS 引擎。注意必须通过 **HTTP 访问**，直接用 `file://` 打开会被浏览器阻止读取本地 JSON 数据文件。

本地预览：

```
cd docs
python -m http.server 8000
```

### 启用联网大模型（可选）

大模型是**增强**而不是前提，不配置也能完整使用。想启用时，三种方式任选：

1. **在界面上填**（最简单）：点击右上角「联网设置」，填入 DeepSeek API Key。Key 只存在浏览器 localStorage，不会上传到任何地方。
2. **环境变量**：设置 `DEEPSEEK_API_KEY`，服务端启动时自动探测。
3. **本地配置文件**：在 `java/` 下新建 `config.local.properties`：

```properties
deepseek.api.key=sk-你的密钥
```

该文件已在 `.gitignore` 里，不会被提交。

> 优先级：界面上填的 > 环境变量 > 本地配置文件。
> 这样设计是为了让「测试密钥」按钮测的一定是你刚填的那把 Key，不会被服务端配置顶掉。

### 验证

```
node tools/equiv-check.js            # 双引擎等价性：28 条用例两侧输出必须逐字节一致
node tools/js-selftest.js            # 只跑 JS 侧
node tools/explain.js "食堂几点开饭"   # 解剖 JS 引擎单条查询的打分过程

cd java
build.bat                            # 编译
java -cp out campus.SelfTest          # 只跑 Java 侧自测
java -cp out campus.SelfTest --explain "食堂几点开饭"   # 解剖 Java 引擎（输出与 explain.js 同口径，可直接比对）
```

`equiv-check.js` 会同时跑两侧的自测，把形如 `查询 \t top1 \t 置信度 \t 覆盖率 \t PASS|FAIL` 的结果行逐行比对，任何一行不一致都会打印出左右两边的原始值。**改动任一侧引擎后都应该跑一次。**

## 算法说明

整个检索过程没有任何机器学习模型，是一条可解释、可复现的流水线。

**1. 归一化** — 全角转半角、转小写、非「汉字/字母/数字」一律替换成空格。标点换成空格而不是删除，避免产生跨标点的伪二元组。

**2. 同义词整串替换** — `synonyms.json` 里逐组做全局替换。按变体长度从长到短排序，保证长词优先。索引端和查询端走同一套替换，所以「餐厅」「饭堂」「伙食」都能命中「食堂」条目。

**3. 混合分词** — 中文按**一元组 + 二元组**切分：`食堂几点开饭` → 单字 `食/堂/几/点/开/饭` 加双字 `食堂/堂几/几点/点开/开饭`。
只用二元组对「换个说法问」召回太差；补上一元组后单字也能命中，召回明显变好。二元组权重 1.0、一元组 0.45，保证真正的词比单字贡献更大。

**4. 停用词过滤** — `的/是/在/什么/怎么样` 这类功能词在两处查询里都会命中，会把无关条目的覆盖率刷虚高。索引端与查询端都按 token 精确过滤。

**5. 多字段 BM25** — `k1=1.2, b=0.75`，字段权重 `question 3.0 / keywords 2.5 / altQuestions 2.0 / answer 1.0`。同一个 token 在不同字段出现，得分按字段权重叠加。

**6. 加权覆盖率** — 命中的查询词权重和 ÷ 查询词权重和。**这是「不硬答」的关键**：不按词个数统计，避免「天」「样」这类常见单字凑出虚高覆盖率。

**7. 置信度分档** — 同时看覆盖率和「第一名与第二名的分差比例」：

- 覆盖率 ≥ 0.7 **且** 分差 ≥ 12% → `high`，直接返回知识库答案
- 覆盖率 ≥ 0.35 → `mid`，返回答案但加一句「我理解得可能不准确」，并列出候选问题
- 否则 → `low`，回答「这个问题我还没学到」，并在配置了 Key 时升级给大模型

**关于错别字**：早期版本做过 Levenshtein 距离 ≤ 1 的自动纠错，实测后**移除**了。中文二元组距离为 1 几乎等价于「两个字里共用一个字」，会把 `今天天气怎么样` 里的 `今天→一天`、`天气→天上` 硬拽到作息类条目上，导致本该说「不知道」的问题被硬答。现在改由一元组兜底（写错一个字仍能命中，只是置信度降为 `mid`），确需支持的常见错别字写进 `synonyms.json` 作为人工整理的混淆表。移除纠错后**所有阈值保持原值未调整**，说明算法本身站得住，不是靠调参凑的结果。

## 知识库数据说明

`docs/data/kb.json` 目前 42 条，分两类，请务必区分：

- **`verified: true`（23 条）** — 来自学校公开信息，`source` 字段写明具体出处（微信公众号文章、北京考试报、首都之窗等）。
- **`verified: false`（19 条）** — **模拟示例数据**，仅用于测试检索效果。答案带 `【示例数据】` 前缀，联系电话用 `010-XXXX XXXX` 占位，界面上打「模拟示例数据」角标。

上线或正式提交前，**必须**把 19 条模拟数据替换为校方真实信息。`meta.integrity_note` 里也写明了这一点。

## 常见问题

**页面提示「以 file:// 直接打开」** — 浏览器禁止 `file://` 页面读取本地 JSON。请用 `java\run.bat`，或在 `docs` 目录下跑 `python -m http.server`。

**徽章一直显示离线模式** — 说明没有可用的 Key。在界面右上角「联网设置」填入即可。若已填仍无效，点「测试密钥」看具体原因（密钥无效 / 网络不可用）。

**改了引擎代码怎么验证** — 改完 `Engine.java` 或 `engine-js.js` 后跑 `node tools/equiv-check.js`，它会同时跑两侧的自测并逐行比对。任何一行不一致都会报出来。

**端口被占用** — 服务会自动从 8080 往后试到 8099。
